Issue #3 — Reject Slack-shaped calls without Slack provenance

Blast Radius · proof-first invariant · implemented and green (6/6 acceptance tests)

Blast Radius may miss something it cannot prove; it must never present something it cannot prove as an Impact.
So slack.files.upload(...) counts only when the receiver provably derives from the affected Slack capability — never from its shape alone.

The proof gate at every call site

flowchart TD
    CALL["call site: slack.files.upload(...)"] --> SHAPE{"receiver is a
    Slack-shaped files.upload?"}
    SHAPE -- "no" --> SKIP["ignore
    (not Slack-shaped)"]
    SHAPE -- "yes" --> PROVEN{"receiver binding is
    a *proven* Slack client?"}
    PROVEN -- "yes" --> MATCH["CodeMatch (direct)
    feeds Impact"]:::pass
    PROVEN -- "no" --> LIM["Limitation:
    receiver is not proven
    to be a Slack client"]:::fail
    classDef pass fill:#14261a,stroke:#3fb950,color:#7ee787

How a binding earns — or loses — provenance

WebClient  ← imported from "@slack/web-api"        (slack-constructor)
slack      ← new WebClient(...)                    (slack-client)   ✔ proven
slack      ← reassigned / shadowed / destructured  (unknown)        ✘ demoted
